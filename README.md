# Real-time-Chat

This repository contains a full-stack, real-time chat application. The frontend is built with Next.js, React, and TypeScript, and styled with Tailwind CSS. The backend is powered by Supabase, utilizing its Postgres Database, Authentication, and Real-time capabilities for a seamless and interactive user experience.

## Features

-   **Real-time Messaging**: Messages appear instantly across all clients in a room without needing to refresh.
-   **User Authentication**: Secure user registration and login handled by Supabase Auth.
-   **Multi-Room Chat**: Users can join, create, and delete different chat channels.
-   **Typing Indicators**: See when other users are typing in the active chat room.
-   **Unread Message Notifications**: A counter displays the number of unread messages in inactive channels.
-   **Persistent Sessions**: User sessions are stored locally, keeping users logged in.
-   **Modern UI**: A responsive and clean user interface built with Tailwind CSS.

## Tech Stack

-   **Frontend**: Next.js, React, TypeScript, Tailwind CSS
-   **Backend**: Supabase
    -   **Database**: Supabase Postgres
    -   **Authentication**: Supabase Auth
    -   **Real-time**: Supabase Realtime Subscriptions

## Getting Started

Follow these instructions to get a local copy up and running.

### Prerequisites

-   Node.js (v20.9 or later)
-   npm, yarn, or pnpm
-   A free [Supabase](https://supabase.com/) account

### 1. Supabase Project Setup

1.  **Create a new Supabase project.**
2.  Navigate to the **SQL Editor** in the Supabase dashboard.
3.  Run the following SQL queries to create the necessary tables:

    ```sql
    -- Create the rooms table
    CREATE TABLE public.rooms (
      name TEXT PRIMARY KEY NOT NULL,
      created_by TEXT,
      created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
    );

    -- Create the messages table
    CREATE TABLE public.messages (
      id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      room TEXT REFERENCES public.rooms(name) ON DELETE CASCADE,
      user_name TEXT,
      content TEXT,
      timestamp TIMESTAMPTZ DEFAULT NOW() NOT NULL
    );

    -- Insert the default 'general' room
    INSERT INTO public.rooms (name, created_by) VALUES ('general', 'system');
    ```

4.  Navigate to **Database** > **Replication** and enable REALTIME for both the `rooms` and `messages` tables.

5.  Navigate to **Authentication** > **Policies** and enable **Row Level Security (RLS)** for both the `rooms` and `messages` tables. Then, create the following policies:

    **For the `messages` table:**
    -   **Policy for Read Access**: Create a new policy from scratch.
        - Name: `Allow authenticated read access`
        - Target Role: `authenticated`
        - `USING` expression: `true`
    -   **Policy for Write Access**: Create a new policy from scratch.
        - Name: `Allow authenticated users to insert messages`
        - Target Role: `authenticated`
        - `WITH CHECK` expression: `true`

    **For the `rooms` table:**
    -   **Policy for Read Access**: Create a new policy from scratch.
        - Name: `Allow authenticated read access`
        - Target Role: `authenticated`
        - `USING` expression: `true`
    -   **Policy for Write/Delete Access**: Create a new policy from scratch.
        - Name: `Allow authenticated users full access`
        - For: `ALL`
        - Target Role: `authenticated`
        - `USING` expression: `true`
        - `WITH CHECK` expression: `true`

6.  (Optional) If you wish to use email confirmation, no further action is needed. To disable email confirmation for easier testing, go to **Authentication** > **Providers** > **Email** and turn off the "Confirm email" setting.

### 2. Local Environment Setup

1.  Clone the repository:
    ```bash
    git clone https://github.com/triggeraustin/real-time-chat.git
    ```

2.  Navigate to the frontend directory:
    ```bash
    cd real-time-chat/chat-frontend
    ```

3.  Create a `.env.local` file in the `chat-frontend` directory by copying the example:
    ```bash
    cp .env.example .env.local
    ```

4.  Add your Supabase Project URL and Anon Key to `.env.local`. You can find these in your Supabase project's **Settings** > **API**.
    ```
    NEXT_PUBLIC_SUPABASE_URL=YOUR_SUPABASE_URL
    NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
    ```

5.  Install the dependencies:
    ```bash
    npm install
    ```

6.  Run the development server:
    ```bash
    npm run dev
    ```

Open [http://localhost:3000](http://localhost:3000) in your browser to see the application.

## How It Works

### Backend (Supabase)

-   **Authentication**: Supabase Auth handles user registration, login, and session management. Usernames are stored in the `raw_user_meta_data` field of the `auth.users` table.
-   **Database**: A Postgres database stores all `rooms` and `messages`. Row Level Security policies ensure that only authenticated users can interact with the data.
-   **Real-time**: The application subscribes to two types of real-time events:
    -   **Postgres Changes**: The frontend listens for `INSERT` and `DELETE` events on the `rooms` and `messages` tables, allowing the UI to update instantly when new messages arrive or rooms are modified.
    -   **Broadcast Events**: Custom events like `typing` are broadcast to clients in a specific room channel to show typing indicators without writing to the database.

### Frontend (Next.js)

-   **`hooks/useSupabaseChat.ts`**: This custom hook is the heart of the application's client-side logic. It manages all interactions with Supabase, including:
    -   Fetching historical messages for the active room.
    -   Subscribing to real-time events for new messages and typing indicators.
    -   Sending new messages.
    -   Creating and deleting rooms.
-   **`components/`**: The UI is broken down into several key components:
    -   `AuthForm`: Handles the login and registration forms.
    -   `ChatRoom`: The main layout after authentication, composing the sidebar and message pane.
    -   `RoomSidebar`: Lists available channels, handles room creation/deletion, and displays the current user's profile.
    -   `MessagePane`: Displays messages for the active room and contains the message input form.
-   **`services/auth.ts`**: A service layer that abstracts the Supabase authentication logic, making it easy to call from the UI.
